# V2-006 — Teaching Sessions

**Status:** in-flight · **Dependencies:** `contract: V2-003, V2-004`
**Wave:** W2 (parallel, no rebase)

## Objective
Turn an installed workflow into an interactive lesson that explains intent, prerequisites, steps, observations and completion criteria while preserving the workflow as the source artifact.

## Owns
TeachingSession identity/state, explanations, checkpoints, learner progress, practice, pause/resume for teaching, and teaching-specific evidence.

## Does not own
Workflow/WorkflowVersion repository persistence (V2-002), canonical WorkflowIR (V2-003), Node/Capability protocol (V2-004), WorkflowRun execution/evidence (V2-005), compiler, computer-agent runtime, scheduling, optimization, reverse teaching, or marketplace economics.

## Must deliver
- TeachingSession bound to an immutable WorkflowVersion;
- step-by-step explanation and optional human practice;
- checkpoints and explicit learner confirmation;
- progress/resume state;
- distinction between teaching evidence and execution evidence;
- no mutation of the installed workflow during teaching.

## Required regressions
Session resume, version pinning, learner progress, incorrect step handling, evidence separation, permission boundaries, and refusal to invent missing workflow facts.

## Dogfooding
Install one real workflow and use it to teach a real operator the task, then record whether the operator can perform the task independently.

## Parallelism contract
V2-006 is independently mergeable with V2-005 and V2-007. It consumes only merged/frozen contracts from W1. It must never branch from or rebase onto a sibling implementation branch. Any teaching↔execution composition is proven later by integration gates.

## Activation
Activated by the sole architect as part of W2A from stable main `bf3036d6032f2c4deedadda7c97948171f06824e`. Implementation branch must use that exact base and must not rebase onto a W2A sibling.
