# V2-001 — Universal Workflow Protocol

**Status:** proposed / architecture bootstrap
**Generation:** WorkflowOS 2.0
**Base:** v1.0 frozen architecture remains authoritative

## Objective

Freeze the protocol boundary shared by WorkflowOS web, desktop, iOS, Android, and cloud execution hosts. This is the first V2 implementation work item and must precede client-specific workflow semantics.

## Required outcomes

- Repository-resident V2-001 protocol design is authoritative for this work item.
- Workflow, WorkflowVersion, Deployment, Node, Capability, Trigger, and Run are explicitly defined.
- WorkflowVersion is immutable and every Run is version-pinned.
- Commands and events are distinct protocol concepts.
- Messages carry protocol version, message identity, correlation, causation, sender/recipient, timestamp, and message type.
- Capability requirements are platform-neutral.
- Placement requirements can express required/preferred/allowed placement and locality/privacy constraints.
- Evidence distinguishes intent, observation, verification, and human confirmation.
- Pause/resume semantics are explicit and idempotent.
- Secret material is never serialized into workflow definitions or ordinary protocol payloads; only opaque secure references are allowed.
- A shared conformance suite is defined before client/runtime-specific implementations.
- V1 compatibility is explicit: V2 does not rewrite the frozen v1.0 workflow/governance architecture.

## Scope

V2-001 is protocol contracts and conformance fixtures only. Do not implement the workflow repository, IR compiler, computer agent, scheduling, marketplace, teaching UI, reverse teaching, or platform applications here.

## Acceptance evidence

The implementation PR must prove protocol round-trip behavior, identity/correlation preservation, command/event separation, capability and placement validation, pause/resume idempotency, authorization/capability separation, secret-reference non-leakage, and cross-client conformance fixtures.

## Dependencies

No V2 product dependency. Reuse of V1 infrastructure is allowed only through explicit adapters and without changing V1 authority semantics.

## Next work

V2-002 consumes the protocol to build the Git-like Workflow/WorkflowVersion repository. V2-003 then defines the canonical WorkflowIR. Later execution, teaching, node, scheduling, marketplace, and self-hosting work must consume these contracts rather than create parallel workflow protocols.
