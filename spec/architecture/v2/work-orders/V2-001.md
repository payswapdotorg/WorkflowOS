# V2-001 — Universal Workflow Protocol

**Status:** COMPLETE  
**Generation:** WorkflowOS 2.0  
**Base:** v1.0 frozen architecture remains authoritative

## Objective
Freeze the protocol boundary shared by WorkflowOS web, desktop, iOS, Android, and cloud execution hosts. This is the first V2 product work item and precedes client-specific workflow semantics.

## Owns
The universal V2 wire protocol, shared semantic message metadata, protocol conformance fixtures, protocol-level capability requirements, placement declarations, execution/evidence message classes, and protocol pause/resume semantics.

## Does not own
Workflow repository/version persistence (V2-002), WorkflowIR semantics (V2-003), Node implementation (V2-004), Run persistence (V2-005), teaching, compiler, computer-agent runtime, scheduling/events, optimization, marketplace/economics, or platform-specific workflow semantics.

## Required outcomes

- Repository-resident V2-001 protocol design is authoritative for this work item.
- Workflow, WorkflowVersion, Deployment, Node, Capability, Trigger, and Run are explicitly defined at the protocol-contract level.
- WorkflowVersion is immutable and every Run is version-pinned.
- Commands and events are distinct protocol concepts.
- Messages carry protocol version, message identity, correlation, causation, sender/recipient, timestamp, and message type.
- Capability requirements are platform-neutral.
- Placement requirements can express required/preferred/allowed placement and locality/privacy constraints.
- Evidence distinguishes intent, observation, verification, and human confirmation.
- Pause/resume semantics are explicit and idempotent.
- Secret material is never serialized into workflow definitions or ordinary protocol payloads; only opaque secure references are allowed.
- A shared conformance suite is defined before client/runtime-specific implementations.
- V1 compatibility is explicit: V2 does not rewrite the frozen v1.0 workflow/governance architecture.

## Scope

V2-001 is protocol contracts and conformance fixtures only. It does not implement the workflow repository, IR compiler, computer agent, scheduling, marketplace, teaching, reverse teaching, or platform applications.

## Acceptance evidence

The implementation proves protocol round-trip behavior, identity/correlation preservation, command/event separation, capability and placement validation, pause/resume idempotency, authorization/capability separation, secret-reference non-leakage, and cross-client conformance fixtures.

## Development-control binding

All later V2 product work is governed by the repository-resident V2 execution control plane at `spec/architecture/v2/execution-control-plane.md`, the machine-readable state at `spec/development-state/v2-work-order-state.json`, and the mandatory dogfooding protocol at `spec/architecture/v2/dogfooding-protocol.md`. Those artifacts define activation, dependencies, evidence, resume semantics, completion and feature-boundary dogfooding so implementation does not depend on conversation history.

## Dependencies

No V2 product dependency. Reuse of V1 infrastructure is allowed only through explicit adapters and without changing V1 authority semantics.

## Next work

V2-002, V2-003 and V2-004 form W1 and consume this merged protocol independently. Their integration behavior is verified by IG-001/IG-002; later execution, teaching, compiler, scheduling, marketplace and self-hosting work must consume these contracts rather than create parallel protocols.
