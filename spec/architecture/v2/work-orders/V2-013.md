# V2-013 — WorkflowOS Self-Hosted Workflow Library

**Status:** planned · **Dependencies:** `implementation: V2-008, V2-009, V2-012, V2-015`
**Wave:** W6 (sequential)

## Objective
Turn WorkflowOS's own software-engineering, maintenance, deployment and governance procedures into installable workflows so WorkflowOS can progressively operate itself.

## Owns
First-party WorkflowOS workflow artifacts, their repository/version manifests, self-hosting installation and safe first-party workflow execution packaging.

## Does not own
Core protocol semantics, WorkflowIR, node/capability authority, generic Run/evidence semantics, computer-agent runtime, scheduling engine, marketplace economics, execution-attestation protocol, execution-proof composition, or bypass mechanisms for development governance.

## Must deliver
- repository of first-party WorkflowOS development workflows;
- workflows for implementation, review, testing, release, maintenance and dogfooding;
- safe self-hosting boundary: workflows cannot bypass authoritative protocol/governance controls;
- versioned workflow installation for development environments;
- evidence that WorkflowOS can consume its own workflow artifacts;
- reuse of the same universal protocol used by third-party/customer workflows;
- proof-consumption conformance where a first-party workflow requires a VerifiedExecutionFact.

## Required regressions
Self-hosting permission boundary, workflow version pinning, failed-workflow recovery, governance preservation, evidence reconstruction, no bypass of authoritative development state, first-party/third-party protocol equivalence, and rejection of invalid/replayed execution-proof predicates where consumed.

## Dogfooding
Use WorkflowOS itself to install and execute at least one development workflow end-to-end, with the repository recording the resulting evidence and any corrective observations. Where an execution predicate is required, the dogfood must verify that the predicate is satisfied by a valid, fresh, authorized execution attestation rather than by an assertion or replay.

## Integration boundary
`IG-005` verifies that self-hosted first-party workflows use the same installation, policy, versioning and execution authorities as third-party workflows and cannot bypass governance. `V2-015` provides the execution-proof capability consumed where required; it does not create a parallel workflow engine.
