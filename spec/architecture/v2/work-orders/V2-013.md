# V2-013 — WorkflowOS Self-Hosted Workflow Library

**Status:** planned · **Dependencies:** `implementation: V2-008, V2-009, V2-012`
**Wave:** W6 (sequential)

## Objective
Turn WorkflowOS's own software-engineering, maintenance, deployment and governance procedures into installable workflows so WorkflowOS can progressively operate itself.

## Owns
First-party WorkflowOS workflow artifacts, their repository/version manifests, self-hosting installation and safe first-party workflow execution packaging.

## Does not own
Core protocol semantics, WorkflowIR, node/capability authority, generic Run/evidence semantics, computer-agent runtime, scheduling engine, marketplace economics, or bypass mechanisms for development governance.

## Must deliver
- repository of first-party WorkflowOS development workflows;
- workflows for implementation, review, testing, release, maintenance and dogfooding;
- safe self-hosting boundary: workflows cannot bypass authoritative protocol/governance controls;
- versioned workflow installation for development environments;
- evidence that WorkflowOS can consume its own workflow artifacts;
- reuse of the same universal protocol used by third-party/customer workflows.

## Required regressions
Self-hosting permission boundary, workflow version pinning, failed-workflow recovery, governance preservation, evidence reconstruction, no bypass of authoritative development state, and first-party/third-party protocol equivalence.

## Dogfooding
Use WorkflowOS itself to install and execute at least one development workflow end-to-end, with the repository recording the resulting evidence and any corrective observations.

## Integration boundary
`IG-005` verifies that self-hosted first-party workflows use the same installation, policy, versioning and execution authorities as third-party workflows and cannot bypass governance.
