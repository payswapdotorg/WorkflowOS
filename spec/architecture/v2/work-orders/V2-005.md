# V2-005 — Workflow Runs + Evidence

**Status:** planned · **Dependencies:** `implementation: V2-002`; `contract: V2-003, V2-004`
**Wave:** W2 (parallel, no rebase)

## Objective
Implement durable Run state and evidence semantics for executions of immutable WorkflowVersions.

## Owns
WorkflowRun identity/lifecycle, step and capability invocation records, evidence persistence, pause/resume/cancel/fail/complete semantics, correlation/causation, idempotent run commands, and dedicated run/evidence tests.

## Does not own
Workflow/WorkflowVersion repository semantics (V2-002), canonical IR semantics (V2-003), Node/Capability definitions (V2-004), computer-use execution (V2-008), scheduling/events (V2-009), teaching, marketplace, or optimization.

## Must deliver
- Run identity pinned to workflow/version/deployment/trigger/input identity;
- step and capability invocation records;
- distinct observation, verification and human-confirmation evidence;
- explicit run state machine for start/pause/resume/cancel/fail/complete;
- idempotent commands with deterministic correlation and causation;
- crash/retry behavior that never treats a model assertion as proof of a side effect;
- PostgreSQL authority with explicit concurrency boundaries.

## Required regressions
Concurrent start, duplicate command, pause/resume race, crash recovery, evidence provenance, version pinning, failed verification, unauthorized completion, and tenant/isolation checks.

## Dogfooding
Execute a real workflow, pause/resume it, inspect its evidence and reconstruct the actual execution history from the recorded run. Record the experiment before completion.

## Parallelism contract
V2-005 may start after V2-002's implementation is merged and the V2-003/V2-004 contracts are merged. It must not consume unmerged sibling implementations from W2. Shared composition is proved by `IG-003` after V2-007 and V2-008 land.
