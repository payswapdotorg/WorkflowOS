# V2-005 — Workflow Runs + Evidence

**Status:** planned  
**Dependencies:** `implementation: V2-002`; `contract: V2-003, V2-004, V2-014`
**Wave:** W2B (after V2-014 contract)

## Objective

Implement durable Run state and evidence semantics for executions of immutable WorkflowVersions, including references to the canonical Execution Attestation protocol.

## Owns

WorkflowRun identity/lifecycle, step and capability invocation records, evidence persistence, pause/resume/cancel/fail/complete semantics, correlation/causation, idempotent run commands, execution-history reconstruction, attestation references/commitment bindings, and dedicated run/evidence tests.

## Does not own

Workflow/WorkflowVersion repository semantics (V2-002), canonical IR semantics (V2-003), Node/Capability definitions (V2-004), ExecutionStatement/ExecutionDigest/ExecutionAttestation protocol semantics (V2-014), computer-use execution (V2-008), scheduling/events (V2-009), teaching, marketplace, or optimization.

## Must deliver

- Run identity pinned to workflow/version/deployment/trigger/input identity;
- step and capability invocation records;
- distinct observation, verification and human-confirmation evidence;
- references to ExecutionDigest/ExecutionAttestation where produced by the configured execution path;
- binding between recorded attestations and the exact Run/attempt/step they describe;
- explicit Run state machine for start/pause/resume/cancel/fail/complete;
- idempotent commands with deterministic correlation and causation;
- crash/retry behavior that never treats a model assertion as proof of a side effect;
- PostgreSQL authority with explicit concurrency boundaries;
- reconstruction of execution history without requiring attestation signatures to be interpreted as verification automatically.

## Required regressions

Concurrent start, duplicate command, pause/resume race, crash recovery, evidence provenance, version pinning, failed verification, unauthorized completion, attestation-binding mismatch, replay/stale-attestation handling at the Run boundary, and tenant/isolation checks.

## Dogfooding

Execute a real workflow, pause/resume it, inspect its evidence and reconstruct the actual execution history from the recorded Run. Where the execution host produces an ExecutionAttestation, verify that the Run references the same statement/digest and that a modified or mismatched attestation cannot be attached as though it described the Run.

## Parallelism contract

V2-005 is separated from W2A to preserve safe parallelism. V2-006 and V2-007 can proceed in parallel with V2-014. V2-005 begins only after V2-014's attestation contract is merged and after V2-002's repository implementation is merged. It must never consume an unmerged sibling branch.

## Completion gate

V2-005 is COMPLETE only after implementation, deterministic verification, required real-system concurrency proofs, attestation-binding proofs, feature-boundary dogfooding, sole architect review/merge, actual merge evidence, and post-merge finalization.

## Stop conditions

Stop and raise a governed V2 architecture change if implementation would require redefining attestation semantics owned by V2-014, treating a signature as automatic side-effect proof, introducing a second evidence/verification authority, or using an unmerged sibling implementation as a dependency.
