# V2-009 — Scheduling + Events + Placement

**Status:** planned · **Dependencies:** `implementation: V2-005, V2-008`
**Wave:** W4 (parallel, no rebase)

## Objective
Make workflows launchable manually, once at a scheduled time, repetitively, or from external/device/application events, with explicit placement and deduplication.

## Owns
Trigger subscriptions, schedule definitions, event matching/deduplication, execution placement resolution, enable/disable semantics, missed-window handling and scheduling/event tests.

## Does not own
Workflow identity/versioning, WorkflowIR, Run lifecycle/evidence, computer-agent execution, teaching/reverse teaching, optimization, marketplace economics, or a second workflow engine.

## Must deliver
- one-shot and recurring schedules;
- event subscriptions with typed event schemas;
- local/cloud/device placement policy;
- event identity and idempotent delivery;
- timezone/time-source correctness;
- retry and missed-window semantics;
- user-visible enable/disable state;
- no hidden autonomous workflow engine outside the V2 protocol.

## Required regressions
Duplicate event, concurrent trigger, missed schedule, timezone boundary, disabled workflow, placement failure, offline device recovery, cross-device delivery and event/run correlation.

## Dogfooding
Run one controlled scheduled workflow and one supported device/application event workflow, verifying duplicate suppression and placement behavior.

## Parallelism contract
V2-009 starts only after the W3 computer-agent implementation is merged. It is independently mergeable with V2-010 and V2-011 and must never use a sibling branch as its base.
