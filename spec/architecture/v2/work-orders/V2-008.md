# V2-008 — Computer-Agent Runtime

**Status:** planned  
**Dependencies:** `implementation: V2-004, V2-005, V2-007`; `contract: V2-014`  
**Wave:** W3 (sequential after W2 + required integration gates)  
**Required gates before activation:** `IG-001`, `IG-002`

## Objective

Provide the computer-use runtime that maps executable workflow plans to real capabilities on desktop, web and mobile hosts without changing workflow semantics, while producing deterministic execution/evidence records and consuming the canonical execution-attestation contract where configured.

## Owns

Agentic/computer-use execution, observation/action grounding, host adapters, human takeover, bounded recovery, and computer-execution evidence.

## Does not own

WorkflowIR semantics, repository/versioning, Run lifecycle/evidence authority, ExecutionStatement/ExecutionDigest/ExecutionAttestation semantics, scheduling/events, teaching, marketplace/economics, or a second workflow protocol/engine.

## Must deliver

- observation/action loop bounded by WorkflowIR and policy;
- capability invocation through the universal protocol only;
- deterministic state/evidence recording;
- ExecutionAttestation production or consumption where the host supports the V2-014 contract;
- pause/resume and human takeover;
- failure classification and recovery without inventing successful side effects;
- host adapters for web, desktop and mobile implementing the same protocol;
- explicit safe-action boundaries for sensitive capabilities;
- no platform-specific workflow semantics;
- honest representation of unsupported attestation assurance.

## Required regressions

Action authorization, stale observation, wrong-target prevention, duplicate action suppression where required, pause/takeover, recovery, evidence truthfulness, attestation binding, stale/replayed attestation handling, cross-host protocol conformance, and locality/privacy enforcement.

## Dogfooding

Automate one useful computer task end-to-end on a real host, including one intentionally recoverable failure and a human takeover path. Where the host supports V2-014, capture an execution attestation and verify it through an independent verifier path; include one tamper/replay negative.

## Integration prerequisites

Before activation, `IG-001` must prove repository↔IR semantics and `IG-002` must prove IR↔capability/placement compatibility. These gates are executed from current `main` after their inputs merge; V2-008 never rebases onto a sibling branch to obtain them.

## Completion gate

V2-008 is COMPLETE only after implementation, deterministic verification, required real-system proofs, attestation/conformance evidence where applicable, feature-boundary dogfooding, sole architect review/merge, actual merge evidence and finalization.

## Stop conditions

Stop and raise a governed V2 architecture change if implementation requires redefining V2-014 attestation semantics, treating a signature as automatic side-effect proof, weakening authorization/locality/evidence boundaries, or creating platform-specific workflow semantics.
