# V2-003 — Workflow IR

**Status:** planned · **Dependency:** `contract: V2-001`
**Wave:** W1 (parallel, no rebase)

## Objective
Freeze the canonical, platform-neutral WorkflowIR representing executable workflow meaning, including control flow, data flow, inputs/outputs, human approval, failure policy, capability requirements, placement constraints and provenance.

## Owns
WorkflowIR schema, graph/control/data semantics, deterministic serialization and semantic digest, validation, compatibility/version negotiation, and dedicated IR tests/specification.

## Does not own
Workflow repository persistence/version lifecycle (V2-002), Node/Capability semantics (V2-004), execution/run state (V2-005), teaching, compiler, computer-agent runtime, scheduling, marketplace, or platform-specific workflow semantics.

## Must deliver
- versioned typed IR with deterministic serialization/digest;
- explicit nodes, edges, data bindings and control semantics;
- human/approval and pause-safe constructs;
- secret references as opaque values only;
- validation that rejects ambiguous/unsupported IR;
- lossless semantic round-trip and compatibility/version negotiation;
- no browser/desktop/mobile/cloud SDK concepts in IR.

## Required regressions
Round-trip identity, deterministic digest, invalid graph rejection, typed binding rejection, secret non-leakage, version compatibility, semantic equivalence across clients, and rejection of platform-specific semantics leaking into IR.

## Dogfooding
Take one real authored workflow, round-trip it through the IR, and verify that user-visible meaning and executable meaning are unchanged. Record the experiment before completion.

## Parallelism contract
V2-003 starts from the same stable `main` SHA as V2-002 and V2-004 after V2-001. It may consume only the merged V2-001 protocol contract. It must never branch from, import from, or rebase onto a sibling's unmerged implementation. Repository/IR composition is proved by `IG-001` after the relevant siblings merge.
