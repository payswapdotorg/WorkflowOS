# V2-003 — Workflow IR

**Status:** planned · **Dependency:** `contract: V2-002`
**Wave:** 2A (parallel with V2-004 after V2-001; V2-002 repository contract is consumed, not its unmerged implementation)

## Objective
Freeze the canonical, platform-neutral WorkflowIR representing executable workflow meaning, including control flow, data flow, inputs/outputs, human approval, failure policy, capability requirements, placement constraints and provenance.

## Must deliver
- versioned typed IR with deterministic serialization/digest;
- explicit nodes, edges, data bindings and control semantics;
- human/approval and pause-safe constructs;
- secret references as opaque values only;
- validation that rejects ambiguous/unsupported IR;
- lossless repository round-trip and compatibility/version negotiation;
- no browser/desktop/mobile/cloud SDK concepts in IR.

## Required regressions
Round-trip identity, deterministic digest, invalid graph rejection, typed binding rejection, secret non-leakage, version compatibility, and semantic equivalence across clients.

## Dogfooding
Take one real authored workflow, round-trip it through the IR, and verify that the user-visible meaning and executable plan are unchanged.

## Parallelism contract
This Work Order may start only from the common merged base that contains V2-001 and the frozen V2-002 repository contract. It must not branch from or depend on the unmerged implementation branch of any sibling Work Order. Its declared surface is the IR package/schema/tests plus its dedicated specification sections; shared files are modified only through a later integration Work Order if necessary.
