# V2-012 — Collaboration + Marketplace + Economics

**Status:** planned · **Dependencies:** `implementation: V2-002, V2-005, V2-006, V2-011`
**Wave:** W5 (sequential)

## Objective
Make workflows repository-like collaborative artifacts that can be public/private, shared, forked, reviewed, installed and monetized.

## Owns
Repository collaboration/visibility extensions, publishing/install distribution, entitlement, creator economics, maintenance subscriptions, and marketplace-specific trust metadata.

## Does not own
Core Workflow/WorkflowVersion identity (V2-002), Run/evidence semantics (V2-005), teaching runtime (V2-006), optimization semantics (V2-011), computer-agent execution, scheduling, or payment-provider-specific workflow semantics.

## Must deliver
- repository permissions and visibility;
- collaboration, forks, provenance and version history;
- publish/install lifecycle;
- creator one-time pricing and maintenance subscriptions;
- entitlement and version-access rules;
- refunds/cancellation/maintenance semantics as explicit domain contracts;
- abuse/reporting and trust metadata;
- no payment provider semantics leaking into WorkflowIR or execution authority contracts.

## Required regressions
Private visibility isolation, fork provenance, concurrent version publication, entitlement enforcement, subscription cancellation, paid-version pinning, creator maintenance updates, execution-authority separation and secret isolation.

## Dogfooding
Use a safe test workflow to fork, modify, publish, install and complete a test transaction; verify creator entitlement and version history.

## Integration boundary
Marketplace entitlement grants content/version access only. It never grants capability authorization, node access, secrets, or execution permission. `IG-005` verifies marketplace↔self-hosting composition.
