# V2-002 — Workflow Repository + Immutable Versioning

**Status:** planned · **Depends:** V2-001

## Objective
Implement the Git-like durable repository model for Workflow and immutable WorkflowVersion. A workflow is an installable/collaborative identity; editing creates a new immutable version.

## Must deliver
- Workflow create/read/update lifecycle with owner/tenant and visibility.
- Immutable WorkflowVersion with content digest, parent version and protocol compatibility.
- Version pinning for installations/deployments.
- Fork semantics preserving provenance while creating a new workflow identity.
- Install/uninstall/enable/disable semantics without mutating historical versions.
- Repository APIs and tests; no execution engine yet.
- Migration is additive and authority remains PostgreSQL.

## Required regressions
- old version remains unchanged after edit;
- deployment remains pinned after a newer version exists;
- fork has independent identity and preserved provenance;
- duplicate version content converges deterministically;
- tenant/private visibility cannot leak across scopes.

## Dogfooding
Create a real workflow, edit it, install both versions, fork it, and execute/inspect the installation path. Record the experiment before completion.
