# V2-004 — Node + Capability Protocol

**Status:** planned · **Dependency:** `contract: V2-001`
**Wave:** W1 (parallel, no rebase)

## Objective
Define and implement the cross-surface Node and Capability protocol. Web, desktop, iOS, Android and cloud hosts expose capabilities through one protocol while retaining platform-specific execution adapters.

## Owns
Node identity, capability advertisement/versioning, capability requirement matching, placement/locality/privacy constraints, node trust/health attributes, and cross-host conformance fixtures.

## Does not own
Workflow repository/versioning (V2-002), WorkflowIR semantics (V2-003), Run/evidence persistence (V2-005), teaching/compiler/computer-agent execution, scheduling/events, optimization, marketplace economics, or platform-specific workflow semantics.

## Must deliver
- authenticated Node identity and platform class;
- capability advertisement, versioning, health/availability and trust attributes;
- capability requirement matching separated from authorization;
- placement constraints: required, preferred, fallback, locality, privacy and human approval;
- protocol conformance fixtures shared across host classes;
- no platform SDK references in WorkflowIR/domain semantics.

## Required regressions
Capability mismatch, unauthorized capability, stale node, placement conflict, privacy/locality violation, protocol-version mismatch, cross-surface conformance, and capability-vs-authorization discrimination.

## Dogfooding
Discover capabilities from two real supported host classes and run the same workflow semantics through both where the required capabilities exist.

## Parallelism contract
V2-004 starts from the same stable `main` SHA as V2-002 and V2-003 after V2-001. It owns only Node, Capability and placement/conformance surfaces and their dedicated tests/specs. It must not depend on or rebase onto sibling implementation branches. Shared integration is verified by IG-002 after the wave lands.
