# V2-011 — Workflow Optimization

**Status:** planned · **Dependencies:** `contract: V2-003`; `implementation: V2-005, V2-008`
**Wave:** W4 (parallel, no rebase)

## Objective
Analyze workflows and propose safer, cheaper, faster or more maintainable implementations without silently changing the executable version.

## Owns
Optimization analysis, opportunity detection, comparison evidence, proposal generation, and creation of explicit candidate WorkflowVersions.

## Does not own
Workflow identity/version authority, Run/evidence authority, computer-agent execution, scheduling/events, teaching, marketplace/economics, or automatic activation of optimized versions.

## Must deliver
- optimization proposals with explicit rationale;
- API substitution suggestions where a stable API is preferable to UI automation;
- reuse suggestions for existing workflows;
- deterministic comparison criteria for correctness, latency, cost, reliability and maintenance;
- proposed changes always materialize as new WorkflowVersions;
- human/owner approval before optimized versions become active.

## Required regressions
Semantic equivalence, proposal provenance, no silent mutation, unsafe optimization rejection, cross-version isolation, and baseline-vs-optimized comparison.

## Dogfooding
Run baseline and optimized versions against the same real task and compare correctness first, then resource cost and maintainability signals.

## Parallelism contract
V2-011 is independently mergeable with V2-009 and V2-010. It may consume merged IR/Run contracts and implementations available at W4 activation, but must never use a sibling branch as a base. Composition is verified by `IG-004`.
